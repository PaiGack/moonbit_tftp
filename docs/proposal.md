# MoonBit TFTP 项目申报书

> 本项目面向 MoonBit 社区库方向，申报一份「协议库 + 客户端 + 服务端」
> 的完整 TFTP 实现。TFTP 规格以 RFC 为准，工程实现为独立编写。

## 项目简介

TFTP（Trivial File Transfer Protocol，简单文件传输协议）是 FTP 的极简版：
跑在 UDP 之上、固定 69 端口、无认证、512 字节块停等传输。它至今活跃在
无盘工作站网络引导、嵌入式设备固件烧写、网络设备配置备份与恢复等场景。

这些场景恰恰是 MoonBit 编译到 `wasm-gc` / `native` 之后最有希望覆盖的地方：
物联网固件工具、边缘设备维护面板、教学用的协议实现示例。但目前 MoonBit
生态里没有一份覆盖完整 TFTP 语义的实现，常见做法是「在 MoonBit 里写一半，
剩下找个 C 库走 FFI」，或者干脆把协议栈搬进一个 JS 沙箱里跑——两者都要
处理跨语言边界，数据验证和内存管理都很别扭。

MoonBit TFTP 想做的是把整条链路——报文编解码、选项协商、客户端、服务端、
CLI——都用 MoonBit 写完，协议层做成不依赖 socket 的纯函数，使其可以在任意
后端上离线测试，也让库的使用者能直接嵌入自己的传输实现。

## 核心功能范围

- **报文层**：RRQ / WRQ / DATA / ACK / ERROR / OACK 的字节级编解码，
  支持畸形报文（截断、非法 opcode、超长字段）的显式错误；
- **选项协商**（RFC 2347 / 2348 / 2349）：`blksize`（8..65464）、
  `timeout`（1..255）、`tsize` 的解析、校验、OACK 生成与拒绝路径
  （ERROR code 8），以及客户端侧回退默认值的能力；
- **通道模式**：`netascii` 的 `\n` ↔ `\r\n`、`\r` ↔ `\r\0` 双向转换，
  含行尾字符跨块边界的处理；`octet` 二进制直传；`mail` 保留接口；
- **客户端**：`get` / `put` 停等状态机，超时重传、重复包去重
  （修复 Sorcerer's Apprentice Syndrome）、block 号 u16 回绕的模比较；
- **服务端**：69 端口监听、每请求独立 TID 会话、并发会话生命周期管理、
  根目录约束与路径穿越防护、完整错误码语义；
- **传输抽象**：客户端与服务端只依赖一个最小的 UDP 收发接口，
  测试时注入内存实现，端到端会话可完全离线运行；
- **CLI**：`cmd/main` 提供 `get` / `put` / `serve` 子命令；
- **测试**：报文往返断言、选项协商矩阵、netascii 边界字符、状态机
  时序事件注入、内存传输上的端到端对拍。

## 与典型 C 实现的思路差异

由于本项目是从零实现而非移植，这里说明与「典型 C 实现」的思路差异：

- **协议层与传输层彻底分离。** C 实现通常把 socket 调用散落在状态机里；
  本项目把编解码、选项协商、模式转换做成纯函数，socket 只存在于一个
  可替换的传输接口之后，测试因此可以完全离线；
- **会话状态机显式化。** 客户端与服务端各有一个显式状态机，
  输入是「收到报文 / 超时」，输出是「要发的报文 / 结果」，
  便于单测覆盖与后续形式化验证；
- **错误处理显式建模。** 不用异常，所有失败路径（畸形报文、选项拒绝、
  权限不足、路径穿越、磁盘满）都作为可枚举的错误值返回；
- **安全默认收紧。** 服务端默认限制在配置的根目录内，拒绝 `..` 穿越，
  并在文档中明确 TFTP 无认证无加密、只应部署在受信任内网；
- **优先 native 后端。** TFTP 依赖宿主 UDP socket，`js` / `wasm` 后端
  的支持程度以沙箱 socket 能力为准，文档中给出平台支持矩阵。
